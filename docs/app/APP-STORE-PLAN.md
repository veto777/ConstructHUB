## A. The two apps

| | ConstructHUB | ConstructHUB CRM |

| Opens | https://constructhub.us (signed-in platform) | https://portal.constructhub.us (the CRM) |

secrets, its own signing storage, its own API key. Nothing is copied from or shared with Remindr (tower rule).

## Lessons from Remindr (48 days to approval; still not downloadable on 2026-10-04)
What went wrong there, and what we do instead:
1. **Guideline 2.1 "Information needed" (12 days lost).** Apple asked for a real-iPhone screen recording (launch,
   sign-up, login, account deletion, purchases, every permission prompt), devices tested, what the app does and for
   whom, setup steps + login, outside services incl. AI, regional differences, regulated-industry proof.
   → All seven answers go in the review notes of the FIRST submission, with the recording attached.
2. **5.1.2(i) tracking: the website's cookie banner showed inside the app.** → In the app: no cookie banner, analytics
   off, no third-party trackers. (`client/src/components/cookie-consent.tsx` must never render in app mode.)
3. **2.1(b) / 3.1.1 purchases: buy buttons were hidden but plan names and prices still showed; a Stripe portal opened
   in the app.** → Decide the money model before 1.0 (see Decisions). If the apps sell nothing: NO plan names, prices,
   "upgrade", cart, pricing page, checkout, Stripe portal, or "buy on our website" anywhere in the app or the listing.
4. **Demo account described as "Premium" in our own notes; replies contradicted each other.** → One demo account per
   state, described identically everywhere; passwords only in secrets, never in git (Remindr committed one).
5. **Fixes lived only on the production server; a deploy would have wiped them mid-review.** → Every compliance change
   is committed; app-mode content is server-flagged and frozen while a version is in review.
6. **"Please resubmit" was read as approval — 10 days lost; availability was never set (0 of 175 countries).**
   → Review status checked through the API with alerts; resubmit the same day; set availability + pricing first.
7. **SDK too old (built with iOS 18.2, iOS 26 SDK required); Swift committed without ever compiling.**
   → Xcode 26 / iOS 26 SDK on the runner; nothing ships that the CI Mac hasn't built; TestFlight on a real iPhone.
8. **A first subscription can't be attached through the API (409) — only in the App Store Connect website.**
   → Only matters if we sell in-app; plan for that one manual tick.
9. **Google sign-in is blocked inside a web view.** → Google sign-in and every Google account connection (Business
   Profile, Ads) run in the system browser sheet (ASWebAuthenticationSession) and come back to the app. Offering Google
   sign-in in the app means also offering **Sign in with Apple** (guideline 4.8).
10. **AI consent (Nov 2025 guideline update) was flagged and never built.** → A consent screen before any personal data
   goes to an outside AI (Hub, Call Assistant transcripts, AI writing tools).

## B. App-friendly pages (web side — starts now, benefits phone browsers too)
- App mode: the native shell identifies itself (user-agent token `ConstructHUBApp/<ver>` / `ConstructHUBCRM/<ver>`);
  the web app reads it once (`client/src/lib/app-shell.ts`) and the server sees it too.
- In app mode: no cookie banner, no analytics, no prices/plans/cart/checkout/Stripe (per the money decision), external
  links open in Safari, Google OAuth through the native browser sheet.
- `viewport-fit=cover` + safe-area padding on every fixed bar (notch, home indicator).
- A bottom tab bar on the platform on phones (the CRM already has one): Home, Call Assistant, Reviews, Locations, More.
- Tap targets ≥ 44 px on touch screens; inputs ≥ 16 px (no iOS zoom on focus).
- An offline screen and a web manifest.
- **Self-serve account deletion** (guideline 5.1.1(v)). Today Settings → Delete account only emails support — Apple
  rejects that outside highly regulated industries. It must cancel billing, remove the user's data and sign them out.

## D. Owner decisions (2026-10-04)
1. **Money: the apps sell nothing** (guideline 3.1.3(f), free companions to the paid web service). Customers sign in
   and use everything they pay for. In the app: no prices, plan names, upgrade/trial prompts, cart, pricing page,
   checkout or Stripe portal; a locked tool says only that it isn't on this account. The store listing never mentions
   buying on the website. Customer payments inside the CRM (homeowners paying contractors' invoices) are physical
   services and stay (3.1.3(e)).
2. **Apple team: Construct Hub LLC** (the team Remindr ships under), with a **new App Store Connect API key just for
   ConstructHUB**. Remindr's key, signing branch and scripts are never reused.
